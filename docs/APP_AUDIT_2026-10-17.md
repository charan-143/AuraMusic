# AuraMusic audit — 17 October 2026

Scope: current source after the UI redesign, plus the existing unit/device checks. Findings below are confirmed control-flow or state-model defects from source review; these individual scenarios have not all been reproduced on the user's phone. No production code was changed during this audit.

## High priority

1. **Imported favorites can become impossible to remove.** `MainScreenViewModel.kt:54-58` unions favorites from two independent stores. `PlaylistRepository.kt:241-292` imports favorites into only its own store. `MainScreenViewModel.kt:808-812` then toggles both stores independently. If one contains the imported ID and the other does not, each tap swaps which store contains it, so their union always remains favorited. Consolidate storage or set both to a shared desired boolean.

2. **Creating a playlist from a song does not add that song.** `MainScreen.kt:421-423` closes the Add-to-playlist sheet before opening the creation dialog. `MainScreenViewModel.kt:636-638` clears `_trackForPlaylist` on close, while `:653-657` relies on that field to add the song. Preserve the pending track through the create flow and clear it only on completion/cancellation.

3. **Data Saver does not select a smaller progressive audio file.** `OnlineMusicSearchService.kt:49-50` upgrades URLs to `_320.mp4`. `MusicPlayerManager.kt:610-627` sets an ExoPlayer bitrate-selection ceiling, but `playTrack` still uses the same single-file URI; no alternate audio rendition is selected. `fallbackLowBitrateUrl` is serialized but never consumed by playback. Choose a validated lower-bitrate URL when applying the preference, retaining playback position. Separately, `AdaptiveAudioCacheManager.kt:97-113` prefetches full upcoming files without checking metered-network/Data Saver policy, adding avoidable mobile data use.

## Medium priority

4. **Crossfade is a fade-out followed by a fade-in, without overlapping songs.** `MusicPlayerManager.kt:888-903` lowers one player's volume near the end; `playTrack` stops and clears that same player before opening the next song (`:342-365`). The next song still needs to prepare, so silence remains possible. Implement actual overlapping playback or name this setting Fade between songs.

5. **Downloads includes every local song.** `MainScreenViewModel.kt:230-239` merges all `isLocal` tracks into `downloadedTracks`, while the download manager lists only managed download requests. The Downloads count and manager can disagree, and items can be shown as downloaded without any managed download to remove. Keep device songs under Songs/Folders and managed downloads under Downloads.

6. **Refreshing device music retains deleted files and old metadata.** `AudioRepository.kt:29-35` only appends unseen IDs; `loadDeviceAudio` calls `addTracks(deviceTracks)` at `:149-150`. It never reconciles the device subset against the latest MediaStore results. Replace the scanned local subset while preserving online songs and user edits; publish empty successful scans as well.

7. **First-run permission grant does not trigger a new scan.** `MainActivity.kt:44-60` requests permissions and creates the UI immediately. The ViewModel scans at startup, but the Activity has no permission-result callback that rescans after access is granted. If the first scan runs before approval, Library stays empty until Refresh or a restart. Trigger a scan from the permission result and distinguish permission denial from an empty library.

8. **Light mode is incomplete in secondary screens.** `PixelQueueSheet.kt:106,196` and `PixelAlbumDetailSheet.kt:127,153,281` use fixed dark Monochrome colors rather than PixelTheme colors. These sheets remain dark when the main screens switch to light mode. Migrate remaining sheets/dialogs to shared theme tokens and verify text contrast in both modes.

## Validation context

The latest production APK built and was installed on the connected Motorola. All 26 unit tests passed. The initial combined device run passed 19 of 20 tests; the new song-menu test assumed a particular fixture song appeared first. After making selection independent of catalog order, both UI tests passed on rerun. Thus all 20 distinct targeted device checks passed across the runs. These checks do not cover the edge cases listed above.

Visual checks of Home, Settings and the expanded player confirmed that the mini-player and navigation occupy separate layout space, artwork loads, and primary controls fit the phone's screen.
