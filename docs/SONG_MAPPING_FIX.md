# Song card audio mapping repair

The recommendation fallback bank paired twelve song titles/artwork entries with only four reused encrypted audio URLs. Yeshanagula and Arz Kiya Hai used the same URL. Removed that fabricated playable bank and the synthetic album-title-as-song records; discovery now displays provider-backed records.

Saved `curated_*` entries and old `album_track_*` placeholders require a matching catalog recording before playback/download. Matching requires normalized title and an expected artist, prefers the album, and rejects unrelated first results. A `resolvedCatalogId` preserves the provider identity while retaining saved playlist/favorite/queue IDs. Old serialized URI/file pointers are invalidated until resolution; successful mappings survive serialization. Old mismatched downloads are marked for retry and their bytes are replaced only after a matching download succeeds, or removed when explicitly deleted. Pending resolution and track transitions cancel when another song is selected or playback is paused.

Public catalog check for Yeshanagula returned the expected Anirudh Ravichander/Singer Prabha/Jangi Reddy recording in The Paradise (Telugu), ID gQsrqA4C, alongside a different artist with the same title; the matching logic selects the expected recording, not the unrelated title match.

Validation: debug app and instrumentation APKs built and installed on Motorola ZD222MKB8C. 32 unit tests passed, including six mapping cases. The combined device run passed all four new mapping/persistence/download/selection-race checks and the existing sixteen reliability/listening checks plus the Home recommendation integration check (21 device checks passed). Three Compose queue/navigation tests could not obtain a UI hierarchy while the phone was locked and asleep; Android window policy confirmed keyguard showing and SCREEN_STATE_OFF. Those UI checks are blocked, not claimed passing. No real audio was played for the fixture tests; playback uses generated silent WAV data.
